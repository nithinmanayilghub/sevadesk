# Story 3.1: Manage Services

## What was built
- A new tenant table `services` (migration 0006): name, duration in minutes, Price in whole paise, `is_active`, created time. Two CHECK constraints: duration 30–480 minutes, Price above 0 and at most ₹10,00,000 (`100_000_000` paise).
- Three Owner-only routes: `GET /api/v1/services` (list), `POST` (add, 201), `PUT /api/v1/services/{id}` (replace every field). Staff and Technicians get 403 on all three.
- No delete. "Deactivate" is a PUT with `is_active: false`. Old Bookings that point at a Service stay valid.
- `list_active_services(session)`: the list that the Chat Page and the Agent will use later. It has no Role check, because Customers call it.
- Money helpers in `frontend/src/lib/money.ts`: `formatRupees` (paise → "₹1,499"), `paiseToRupeesText` (paise → "1499" for an input box), `rupeesToPaise` ("₹1,499" → 149900, or null).
- Settings → Services page (`/app/settings/services`), Owner only: list, add form, edit in place, Deactivate / Activate.

## Why
- Money is whole paise, never floats: `0.1 + 0.2` is not `0.3` in floats, but `10 + 20` is always `30`.
- The backend owns every rule. The form only turns text into numbers. It sends null for bad text, and the backend answers with the message next to the field.
- Three layers check a Price: the form (`rupeesToPaise`), the API (`check_price` in `schemas.py`), and the database (`ck_services_price_valid`). Each layer catches what the one before it can miss.
- The Role check runs before the lookup. So Staff always get the same 403, and a 403 vs 404 never tells them which ids exist.

## Data flow
Owner types "1,499" → `rupeesToPaise` → 149900 → `POST /api/v1/services` → CSRF origin check → `ActorDep` (who is it, which Business) → `require_roles(MANAGE_SETUP)` → Pydantic `ServiceIn` (strict ints, copy for each field) → `ServiceRepository.add` (sets `business_id`, flush) → DB CHECKs → 201 `ServiceOut` → page loads the list again → `formatRupees(149900)` → "₹1,499".

## Concepts learned
1. Store money as whole paise. Turn it into rupee text only on the screen.
2. Defence in depth (several layers each check the same rule): the form, the API, and the database.
3. Role check before lookup: the same 403 for every id, so no record leaks.
4. Soft deactivation: turn a record off instead of deleting it, so old records that point at it stay valid.
5. A full replace (PUT) needs every field, `is_active` too. A missing field must not quietly reset a value.
6. Strict ints: without them, JSON `true` would be saved as 1 paise.

## Surprises
- `test_hello.py` also listed every table. Only the full test run found it. Lesson: run the full suite, not only the new file.
- Vitest timed out when the Docker stack used all the CPU. With the stack stopped, every run passed.
- In the hands-on task, `formatRupees` and `rupeesToPaise` were easy to swap. They go in opposite directions: paise → text, text → paise.
- Frontend tests fail in WSL ("Cannot find native binding"), because `node_modules` was installed on Windows. From WSL, run them with `powershell.exe -NoProfile -Command "npx vitest run ..."`.
