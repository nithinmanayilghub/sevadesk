# Story 2.5: Invite team members and manage the team

## What was built
- A new tenant table `invites` (migration 0004). It keeps only a SHA-256 hash of each token. The database refuses an invite with the Owner Role or with no Role.
- The Owner makes an invite link: `POST /api/v1/team/invites`. The raw token is shown once. The link works once and expires after 7 days. SevaDesk sends no email.
- The invited person opens `/invite/{token}`, sets a password, and is logged in: `POST /api/v1/invites/preview` and `POST /api/v1/invites/accept`.
- Settings → Team (`/app/settings/team`): the Owner sees all members, changes Staff / Technician, and deactivates or reactivates a member. Deactivation deletes all of that member's sessions at once.
- `active_technician_ids` in `accounts/service.py`: the one place that says who counts as an active Technician. The Team page says "Just you for now" when that list is only the Owner.
- The OpenTelemetry Collector rewrites `/invite/<token>` to `/invite/:token` in every span, so traces never hold a working link.

## Why
- An Owner must share the work with Staff and Technicians (FR-9), without an email service in the MVP.
- A token is like a password: store only its hash, use it once, keep it out of URLs that servers log.
- Deactivate, never delete: old Bookings must still point at this person (AD-4).
- Delete sessions at once: a removed person must lose access now, not in 7 days (AD-5).

## Data flow
Accept: browser `POST /invites/accept {token, password}` → `_valid_invite`: hash the token, find the invite in `system_scope("invite_accept")` with `SELECT … FOR UPDATE` (row lock) → used / expired / unknown: 404 `This invite is no longer valid.` → `tenant_scope(invite.business_id)` → `_create_user` (User + membership with the invited Roles) → `used_at = now` → `start_session` → cookie + permissions.

Deactivate: `PATCH /team/members/{id} {"is_active": false}` → `require_roles(MANAGE_SETUP)` (403) → `get_or_raise` (404 for another Business) → team rules (422) → `is_active = false` + `delete_for_user` → new team list. The member's next request → no session → 401 → `/login`.

## Concepts learned
1. Single-use secret tokens: random, hashed in the DB, shown once, marked used.
2. Row lock (`SELECT … FOR UPDATE`): a second transaction waits until the first commits, then reads the new row. It stops a race condition.
3. Soft deactivation: turn a row off instead of deleting it, so links to it stay valid.
4. Secrets in URLs leak: logs, traces, browser history, Referer headers. Keep them in the body; mask what you cannot avoid.
5. React context: one value shared with every component inside a provider, without passing it through each one.

## Surprises
- Caddy writes the full page path into the span attribute `url.path`, and Caddy cannot turn that off. The fix moved to the collector.
- In a Caddyfile, `{token}` is a placeholder. An unknown placeholder becomes empty text.
- A whole-body Pydantic check (`model_validator`) has no field name, so our error envelope shows only the general message.
- Never run `git` inside WSL on this repo: it shows every file as changed (line ends). Use Windows git.
