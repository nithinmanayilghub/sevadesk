# Story 2.6: Choose light or dark theme

## What was built
- A new column `users.theme` (migration 0005): `system`, `light` or `dark`, default `system`. A CHECK constraint makes the database refuse any other value.
- `GET /api/v1/me` (and the log-in and invite-accept replies) now include `theme`. `PUT /api/v1/me/theme {"theme": "dark"}` saves it and answers 204.
- In the browser, one label decides the theme: `<html data-theme="light|dark">`. No label = follow the device.
- Only the `/app` layout writes the label (from `/me`), and its cleanup removes it when you leave `/app`. So public pages always follow the device.
- Each color token holds both values in one line: `--background: light-dark(#f4f4f5, #09090b)`. `color-scheme` picks which one. Tailwind's `dark:` styles follow the same rule.
- Settings → Appearance (`/app/settings/appearance`), open to every Role: System / Light / Dark radios.

## Why
- The choice must follow the person to another device (acceptance rule), so it lives on the server, not in `localStorage`.
- It belongs to the person, not to a Business, so it is on `users`, not on `memberships`.
- "No label" already means "follow the device", so System reuses that state instead of adding a third one.

## Data flow
Tap Light → `setTheme("light")` (screen changes at once) → `PUT /me/theme` → `set_theme` updates the caller's own `users` row → 204.
Save fails → `setTheme(old)` + "Could not save. Please try again."
Another device → log in → `GET /me` → `theme: "light"` → layout effect → `applyTheme("light")` → `<html data-theme="light">` → CSS.

## Concepts learned
1. A user preference saved on the server travels with the person to every device.
2. Optimistic update: show the change now, save it, undo it if the save fails.
3. Effect cleanup: code React runs when a component leaves the screen. Without it, the label leaks onto public pages.
4. Migrations undo in reverse order: drop the constraint first, then the column.
5. A disabled control loses keyboard focus. To block a second action, ignore it in code instead.

## Surprises
- The build tool (Lightning CSS) rewrote `light-dark()` into its own on/off variables. Same behaviour, different text.
- The final review found the keyboard-focus bug. jsdom (the fake browser in tests) does not move focus, so only a review or a real browser shows it.
- Known small flash: on a full reload of `/app`, the device theme shows until `/me` answers.
