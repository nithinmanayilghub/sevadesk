# Glossary

Plain-word meanings. Newest terms at the bottom.

- **Reverse proxy** - A server that sits in front of your apps. It receives every request and passes each one to the right app. Caddy is ours.
- **Origin** - The triple of scheme, host and port, like `http://localhost:80`. Browsers treat different origins as separate places.
- **CORS** - A browser rule that blocks a page from calling a different origin unless that origin allows it. One origin means no CORS trouble.
- **Migration** - A small script that changes the database structure (add a table, add a column). Migrations run in order, so every database ends up the same.
- **ORM** - Object-Relational Mapper. A tool that lets you use Python classes instead of writing raw SQL. SQLAlchemy is ours.
- **OpenAPI** - A standard file that describes an API: its paths, inputs and outputs. Tools can read it to build docs and client code.
- **Transaction** - A group of database changes that succeed together or fail together. If one fails, a rollback undoes them all. In SevaDesk, the `get_session` dependency owns the transaction; services never commit.
- **Env var** - A setting kept outside the code, in the environment. We use it for things like the database URL, so secrets stay out of code.
- **Testcontainers** - A test tool that starts a real Docker container (here, Postgres 18) for a test, then removes it. Tests run against the real thing.
- **Caddy** - Our reverse proxy and web server. It is the front door: every browser request hits Caddy first.
- **FastAPI** - A Python framework for building web APIs. It also writes the OpenAPI description for us.
- **Postgres** - Our database. It stores data in tables and keeps it safe, even if the app restarts.
- **Docker** - A tool that runs programs in sealed boxes called containers. Each box has everything the program needs, so it runs the same on every computer.
- **Health check** - A small test that asks a program, "Can you do your job now?" It answers yes or no.
- **Readiness** - A program is ready when it runs and its dependencies (database, cache) answer. Compose `service_healthy` waits for this.
- **Heartbeat** - A signal a program sends again and again to show it is alive. If the signal stops, the program is probably dead.
- **TTL** - Time to live. A stored key deletes itself after this time. Our worker heartbeat has a TTL of 30 s.
- **Cron** - A rule that runs a job on a schedule. Ours runs the heartbeat every 10 s.
- **SAQ** - Simple Async Queue. A Python tool that runs background jobs from a queue. Our worker uses it.
- **Valkey / Redis** - A fast store that keeps data in memory. We use it for queues and the heartbeat. Valkey is the open-source copy of Redis; they speak the same protocol.
- **Error envelope** - One fixed shape for every error we raise on purpose (an `AppError`): `{"error": {"code", "message"}}`. FastAPI's own 422 and 500 errors do not use it yet.
- **503** - HTTP status "Service Unavailable". The API runs, but something it needs does not work.
- **Worker** - A second program that runs beside the website. It does slow jobs in the background (for example, asking the AI for a reply), so the website can answer people fast.
- **Eval** - An automated exam for the AI Agent. It gives the Agent fixed test messages and checks each reply in code.
- **Check** - A small piece of code that looks at one reply and says pass or fail.
- **Score** - The share of cases that passed one check, from 0.00 to 1.00.
- **Baseline** - The best scores so far, saved in `evals/baseline.json`. A score below it fails the eval.
- **Golden Dataset** - The reviewed set of test cases that the Evals use. Today it has one placeholder case; Epic 7 adds 30 real ones.
- **Exit code** - The number a program gives back when it ends. `0` means ok; any other number means a problem. CI reads it.
- **Placeholder** - A simple stand-in for something that does not exist yet.
- **CI** - Continuous Integration. A robot that runs your checks on every change, on a clean machine.
- **Pipeline / Job / Step** - A pipeline is the whole CI run. A job is one stage of it. A step is one command inside a job.
- **Lint** - A tool reads your code and warns about style problems and common bugs. Ours: ruff (Python) and ESLint (frontend).
- **Formatter** - A tool that only changes how code looks (spaces, line breaks). It does not change what the code does.
- **Import contract** - A rule about which files may import which. Ours: `app.core` must not import the entry points.
- **Coverage** - The share of code lines that tests run. Our backend must stay at 80% or more.
- **Alembic head** - The newest migration. The repo must have exactly one.
- **Downgrade** - A migration step that undoes an upgrade. We test that the database can go to empty and back.
- **OpenAPI drift** - The API changed, but the saved `openapi.json` and frontend types did not. CI fails when this happens.
- **Branch protection** - GitHub rules on a branch, such as "checks must pass before a merge" and "no force pushes".
- **Required check** - A CI check that must be green before GitHub allows a merge.
- **Pull request (PR)** - A request to merge one branch into another. CI runs on it.
- **Fork** - A copy of a repo owned by someone else. A fork PR always gets a read-only token.
- **GITHUB_TOKEN** - The temporary key a workflow gets. The `build` job gets a token that can write packages, on `main` and on PRs from this repo. It logs in and pushes only on a push to `main`. Fork PRs always get a read-only token.
- **Container image** - A saved package of a program and everything it needs. Docker starts containers from it.
- **Multi-arch image** - One image name that works on two chip types: amd64 (most PCs) and arm64 (Apple chips, some servers).
- **GHCR** - GitHub Container Registry, `ghcr.io`. The place where we store our images.
- **QEMU** - An emulator. It lets an amd64 machine build the arm64 image.
