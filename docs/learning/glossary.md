# Glossary

Plain-word meanings. Newest terms at the bottom.

- **Reverse proxy** - A server that sits in front of your apps. It receives every request and passes each one to the right app. Caddy is ours.
- **Origin** - The triple of scheme, host and port, like `http://localhost:80`. Browsers treat different origins as separate places.
- **CORS** - A browser rule that blocks a page from calling a different origin unless that origin allows it. One origin means no CORS trouble.
- **Migration** - A small script that changes the database structure (add a table, add a column). Migrations run in order, so every database ends up the same.
- **ORM** - Object-Relational Mapper. A tool that lets you use Python classes instead of writing raw SQL. SQLAlchemy is ours.
- **OpenAPI** - A standard file that describes an API: its paths, inputs and outputs. Tools can read it to build docs and client code.
- **Transaction** - A group of database changes that succeed together or fail together. If one fails, a rollback undoes them all. In SevaDesk, the `get_session` dependency owns the transaction; services never commit.
- **Env var** - A setting kept outside the code, in the environment. We use it for things like the database URL, so secrets stay out of code.
- **Testcontainers** - A test tool that starts a real Docker container (here, Postgres 18) for a test, then removes it. Tests run against the real thing.
- **Caddy** - Our reverse proxy and web server. It is the front door: every browser request hits Caddy first.
- **FastAPI** - A Python framework for building web APIs. It also writes the OpenAPI description for us.
- **Postgres** - Our database. It stores data in tables and keeps it safe, even if the app restarts.
- **Docker** - A tool that runs programs in sealed boxes called containers. Each box has everything the program needs, so it runs the same on every computer.
- **Health check** - A small test that asks a program, "Can you do your job now?" It answers yes or no.
- **Readiness** - A program is ready when it runs and its dependencies (database, cache) answer. Compose `service_healthy` waits for this.
- **Heartbeat** - A signal a program sends again and again to show it is alive. If the signal stops, the program is probably dead.
- **TTL** - Time to live. A stored key deletes itself after this time. Our worker heartbeat has a TTL of 30 s.
- **Cron** - A rule that runs a job on a schedule. Ours runs the heartbeat every 10 s.
- **SAQ** - Simple Async Queue. A Python tool that runs background jobs from a queue. Our worker uses it.
- **Valkey / Redis** - A fast store that keeps data in memory. We use it for queues and the heartbeat. Valkey is the open-source copy of Redis; they speak the same protocol.
- **Error envelope** - One fixed shape for every error we raise on purpose (an `AppError`): `{"error": {"code", "message"}}`. FastAPI's own 422 and 500 errors do not use it yet.
- **503** - HTTP status "Service Unavailable". The API runs, but something it needs does not work.
- **Worker** - A second program that runs beside the website. It does slow jobs in the background (for example, asking the AI for a reply), so the website can answer people fast.
- **Eval** - An automated exam for the AI Agent. It gives the Agent fixed test messages and checks each reply in code.
- **Check** - A small piece of code that looks at one reply and says pass or fail.
- **Score** - The share of cases that passed one check, from 0.00 to 1.00.
- **Baseline** - The best scores so far, saved in `evals/baseline.json`. A score below it fails the eval.
- **Golden Dataset** - The reviewed set of test cases that the Evals use. Today it has one placeholder case; Epic 7 adds 30 real ones.
- **Exit code** - The number a program gives back when it ends. `0` means ok; any other number means a problem. CI reads it.
- **Placeholder** - A simple stand-in for something that does not exist yet.
- **CI** - Continuous Integration. A robot that runs your checks on every change, on a clean machine.
- **Pipeline / Job / Step** - A pipeline is the whole CI run. A job is one stage of it. A step is one command inside a job.
- **Lint** - A tool reads your code and warns about style problems and common bugs. Ours: ruff (Python) and ESLint (frontend).
- **Formatter** - A tool that only changes how code looks (spaces, line breaks). It does not change what the code does.
- **Import contract** - A rule about which files may import which. Ours: `app.core` must not import the entry points.
- **Coverage** - The share of code lines that tests run. Our backend must stay at 80% or more.
- **Alembic head** - The newest migration. The repo must have exactly one.
- **Downgrade** - A migration step that undoes an upgrade. We test that the database can go to empty and back.
- **OpenAPI drift** - The API changed, but the saved `openapi.json` and frontend types did not. CI fails when this happens.
- **Branch protection** - GitHub rules on a branch, such as "checks must pass before a merge" and "no force pushes".
- **Required check** - A CI check that must be green before GitHub allows a merge.
- **Pull request (PR)** - A request to merge one branch into another. CI runs on it.
- **Fork** - A copy of a repo owned by someone else. A fork PR always gets a read-only token.
- **GITHUB_TOKEN** - The temporary key a workflow gets. The `build` job gets a token that can write packages, on `main` and on PRs from this repo. It logs in and pushes only on a push to `main`. Fork PRs always get a read-only token.
- **Container image** - A saved package of a program and everything it needs. Docker starts containers from it.
- **Multi-arch image** - One image name that works on two chip types: amd64 (most PCs) and arm64 (Apple chips, some servers).
- **GHCR** - GitHub Container Registry, `ghcr.io`. The place where we store our images.
- **QEMU** - An emulator. It lets an amd64 machine build the arm64 image.
- **Span** - One timed step of work, like "the SQL query took 1 ms". It has a start time, a length, and notes (attributes).
- **Trace** - The tree of spans for one request. All its spans share one trace ID, so tools can draw them as one picture.
- **traceparent** - A short text label, like `00-<trace id>-<span id>-01`. It carries the trace ID from one program to the next, in an HTTP header or inside a job.
- **Context propagation** - Passing the traceparent along, so the next program joins the same trace instead of starting a new one.
- **OpenTelemetry (OTel)** - An open standard and set of libraries for traces, logs, and metrics. Many tools (Grafana, Datadog, …) accept it, so you can switch tools without changing code.
- **OTLP** - The OpenTelemetry Protocol: the format OTel uses to send data. We send it over HTTP to port 4318.
- **Exporter** - The part of the app that sends spans or logs out, to a collector or a tool.
- **Collector** - A relay program. It receives telemetry from all apps and sends it to one destination, set by config.
- **PII masking** - Hiding personal data (Personally Identifiable Information), like phone numbers and addresses, before it is stored or sent.
- **Waterfall view** - The trace picture in Grafana. Each bar is a span: where it starts is when it began, its length is how long it took.
- **VM (virtual machine)** - A rented computer in a data centre. One big server is split into pieces; each piece acts like its own computer. Our demo runs on one DigitalOcean droplet.
- **SSH** - A safe way to log in to another computer over the internet and run commands there. It uses a key pair instead of a password.
- **Key pair** - Two linked files. The private key stays secret with you. The public key goes to the other side. Together they prove who you are.
- **Deploy key** - A key pair only for the CI deploy job. Its private half is a GitHub secret; its public half is on the VM.
- **known_hosts** - A list of servers your SSH client trusts. It stops a fake server from pretending to be ours.
- **GHCR** - GitHub Container Registry: GitHub's store for Docker images (`ghcr.io`).
- **GitHub environment** - A named target (ours is `demo`) that holds its own secrets and variables and lists every deploy.
- **sslip.io** - A free name service: `140-238-1-2.sslip.io` always points to IP `140.238.1.2`. It gives us a domain name, so Caddy can get an HTTPS certificate.
- **AOF (append-only file)** - Valkey writes every change to a file on disk, so data survives a restart.
- **Migrate first, then switch** - Deploy order: change the database, and only then start the new code. A failed migration leaves the old version running.
- **`set -e`** - A shell setting: stop the script at the first command that fails.
- **Out of capacity** - The cloud has no free space for the VM size you asked for right now. It is temporary; try again later.
- **Droplet** - DigitalOcean's name for a VM.
- **Swap** - Disk space that Linux uses as extra memory when the real memory is full. Slow, but it stops a crash at a memory peak.
- **Base64** - A way to write any data with 64 safe letters (`A–Z`, `a–z`, `0–9`, `+`, `/`). It often ends with `=` or `==` as padding.
- **Passphrase** - A password that protects a private key file. Without it, the key file alone is enough to log in, so keep that file private.
- **Terraform** - A tool that reads text files describing cloud resources, and then creates, changes, or deletes resources until the cloud matches the files ("infrastructure as code").
- **Terraform state** - Terraform's memory: a file listing what it created and the real IDs. Without it, Terraform cannot change or delete those resources. Ours lives in an S3 bucket, so the laptop and GitHub share it.
- **`terraform plan` / `apply` / `destroy`** - Plan shows what would change and changes nothing. Apply makes the changes. Destroy deletes everything that the state lists.
- **Mock provider** - A fake AWS used by `terraform test`. No AWS calls, no credentials, no cost. It invents IDs, so tests set fixed values where an assert needs them.
- **IAM role** - A set of AWS rights that a person or a program borrows for a short time. No stored keys.
- **Trust policy** - The part of a role that says WHO may borrow it (ours: one GitHub environment and the laptop user).
- **Permissions boundary** - A hard upper limit on a role. Even if the role gets more rights attached, it can never do more than the boundary allows.
- **OIDC (GitHub to AWS)** - GitHub gives a running job a short-lived signed token that says "repo X, environment Y". AWS checks it and lends the role. No AWS keys are stored in GitHub.
- **Fargate** - AWS runs our containers for us. We never manage a server.
- **ECS task definition / service** - The task definition is the recipe for a container (image, size, settings). The service keeps one copy running and restarts it if it dies.
- **ALB (Application Load Balancer)** - AWS's front door. It sends `/api/*` to the backend and everything else to the frontend, like Caddy does on the demo.
- **Security group** - A firewall around one resource. It lists who may connect, by port and by source.
- **NAT gateway** - A paid AWS box (about $1 per day) that lets private servers reach the internet. We avoid it: our tasks sit in public subnets with public IPs, guarded by security groups.
- **Environment protection rule** - A GitHub rule on an environment (ours: `aws-staging`) that makes a job wait for a named person to click "Approve".
- **Tenant** - One customer company that shares the app with others. In SevaDesk, a tenant is one Business. Its rows carry its `business_id`.
- **Multi-tenancy** - Many tenants in one database. The code must make sure each tenant sees only its own rows.
- **ContextVar** - A Python variable with a separate value for each request. We keep the current Business in one, so requests never mix.
- **System scope** - A rare, logged permission to look across all Businesses, for example "does this email already exist?" during sign-up. Only listed callers may use it.
- **Hash** - A one-way scramble of data. You can check a password against it, but you cannot get the password back from it.
- **Salt** - Random data mixed into each password hash, so two people with the same password get different hashes.
- **Argon2id** - A slow, memory-hungry password hash. Slow on purpose, so guessing millions of passwords costs too much.
- **Rollback** - Undoing every change in a transaction after an error, so the database stays as it was.
- **Flush** - Sending pending changes (INSERTs) to the database now, inside the open transaction, without committing them.
- **Design token** - A named design value, like `--brand: #047857`. Components use the name, so one file changes the whole look.
- **unicode-range** - A font rule that says which characters a font file covers. The browser downloads the file only if the page uses one of those characters.
- **Layers contract** - An import-linter rule: higher layers may import lower ones, never the reverse (`business` → `accounts` → `core`).
- **Session token** - A long random string the server gives the browser at log-in. The browser sends it back on every request; the server looks it up to know who you are.
- **Cookie flags** - Rules on a cookie. `HttpOnly`: page scripts cannot read it. `Secure`: sent only over https. `SameSite=Lax`: not sent when another site POSTs to us. `__Host-` name prefix: only our exact site can set it.
- **CSRF** - Cross-site request forgery. A page on another site makes your browser send a request to us, with your cookie. We stop it by checking the `Origin` header.
- **Origin header** - A header the browser adds to a request. It names the site that started the request. A page cannot change it.
- **Rate limit** - A cap on how many tries one key (an account, an IP) gets in a time window. After the cap: a fixed lock (429).
- **Race condition** - A bug that appears only when two things run at the same moment, for example 10 log-in tries that all read a count of 0.
- **X-Forwarded-For** - A header a proxy adds with the client's IP. Only the last value (written by our own proxy) can be trusted.
- **User enumeration** - Finding out which emails have accounts from different replies or reply times. We give the same reply and do the same work for both.
- **NFKC** - A Unicode rule that turns characters typed different ways (like "é") into one form, so the same password always matches.
- **Back-forward cache (bfcache)** - A frozen copy of a page that the browser shows on Back without loading it again. The `pageshow` event with `persisted: true` tells the page it was restored.
- **Tenant isolation suite** - The tests marked `isolation`. They list every endpoint and prove that one Business cannot reach another Business's data. CI runs them as their own step.
- **Composite foreign key** - A link that uses two columns, like `(business_id, membership_id)` → `(business_id, id)`. The database then refuses a link into another Business.
- **Banned API** - A Ruff rule (`TID251`) that blocks an import, like `sqlalchemy.text`, outside allowed folders.
- **Context copy into a thread pool** - When FastAPI runs a sync route in a worker thread, it copies the request's ContextVars into it. Values set inside a sync dependency are not copied back.
- **404-not-403** - Answer "not found" for another Business's record, so the caller cannot learn that it exists.
- **Positive control** - A test that shows the normal case works (for example, a write really writes), so a "nothing changed" result in another test is real.
- **Authorization** - Checking what a known User may do. Authentication (log-in) answers "who are you"; authorization answers "may you do this".
- **Permission** - One action from the FR-10 table, like `manage_setup`. The backend says which Roles have it.
- **403 Forbidden** - "We know who you are, but your Role may not do this." Not the same as 401 ("log in first") or 404 ("not found").
- **Union of Roles** - A User with two Roles may do everything either Role may do.
- **BOM** - Byte order mark: 3 hidden bytes some Windows tools put at the start of a UTF-8 file. Most code tools do not want them.
- **Invite token** - A long random string inside an invite link. It works like a one-time password: the database keeps only its hash.
- **Single-use link** - A link that works once. After use, the server marks it used (`used_at`) and refuses it.
- **Row lock (`SELECT … FOR UPDATE`)** - A query that locks the rows it reads. Another transaction that wants the same rows waits until the first one commits.
- **Soft deactivation** - Turning a record off (`is_active = false`) instead of deleting it, so other records that point at it stay valid.
- **React context** - A way to share one value (like the User's permissions) with every component inside a provider, without passing it through each component.
- **Clipboard API** - `navigator.clipboard.writeText(text)`: the browser copies text for the User, so they can paste it.
- **Referer header** - A header the browser sends with the address of the page you came from. `referrer: "no-referrer"` turns it off for a page.
- **Span name / span attribute** - A span is one step in a trace. Its name is a short label; its attributes are key-value details, like `url.path`.
- **Collector processor** - A step inside the OpenTelemetry Collector that changes telemetry before it is sent on, like rewriting a secret in a span.
- **Placeholder (Caddy)** - Text like `{http.request.uri.path}` that Caddy replaces with a value. An unknown one becomes empty.
- **data-theme** - A label we put on the `<html>` tag (`data-theme="dark"`). The CSS reads it to pick the colors. No label means "follow the device".
- **color-scheme** - A CSS property that tells the browser "this page is light" or "dark". It also colors scrollbars and form controls.
- **light-dark()** - A CSS function that holds two colors, `light-dark(light, dark)`. The browser picks one from `color-scheme`.
- **Custom variant (Tailwind)** - Our own rule for when a prefix like `dark:` applies. Ours: a chosen theme wins; with no choice, the device decides.
- **Optimistic update** - Show a change on screen before the server says yes, then undo it if the save fails. It makes the app feel instant.
- **Effect cleanup** - The function an effect returns. React runs it when the component leaves the screen, or before the effect runs again.
- **aria-busy** - An attribute that tells screen readers "this part is still working". We set it while a save runs.
- **Paise** - The smallest unit of Indian money: ₹1 = 100 paise. We store every Price as a whole number of paise, so there are no float rounding errors.
- **CHECK constraint** - A rule inside the database table, like `price_paise > 0`. The database refuses any row that breaks it, even if the app has a bug.
- **Defence in depth** - Checking the same rule in more than one layer (form, API, database), so one missed check does not let bad data in.
- **Role check before lookup** - Check "is this person allowed?" before "does this record exist?". Then everyone without access gets the same 403, and learns nothing about which ids exist.
- **Full replace (PUT)** - A PUT sends every field of a record, and the server replaces them all. A missing field is an error, not "keep the old value".
- **StrictInt** - A Pydantic type that accepts only a real JSON whole number. Without it, `true`, `"499"` or `499.0` would quietly become numbers.
- **Intl.NumberFormat** - The browser's built-in number formatter. With `en-IN` and `INR`, it writes ₹1,00,000 with Indian grouping (lakh, crore).
- **useId** - A React hook that gives each component its own unique id, so two forms on one page never share a label id.
- **aria-disabled** - Tells screen readers "this button does nothing now", but keeps the button focusable. We use it instead of `disabled`, which drops keyboard focus.
- **Clock time vs moment** - A clock time is "10:00" with no date ("every Monday at 10"). A moment is one exact point in history ("25 Dec 2026, 10:00 in India"). Working Hours are clock times (`time`); bookings will be moments (`timestamptz`).
- **Timezone (IANA name)** - The clock rules of a place, written like `Asia/Kolkata`. The same moment is a different date and time in different timezones.
- **Field validator vs model validator** - A field validator checks one field, and its error lands on that field (`tuesday.end_time`). A model validator checks the whole object, and its error lands on the object (`tuesday`).
- **mode="before"** - A Pydantic validator that sees the raw JSON value before Pydantic's own checks. We use it so every bad input gets our own message and the field ends up the right type.
- **Row lock (SELECT … FOR UPDATE)** - Reading a row and locking it until the transaction ends. A second request that wants the same lock waits, so two saves run one after the other.
- **Dotted field path** - The name of a field inside another field, joined with dots: `tuesday.end_time`, or `roles.0` for the first item in a list.
- **Device toolbar** - Chrome's tool (F12, then Ctrl + Shift + M) that shows a page at a phone's width.
- **Slug** - A short, URL-safe name for a thing, such as `cafe-ravi-94j2w5`. Only lowercase letters, digits and `-`. Ours never changes, so a shared link keeps working.
- **Public endpoint** - An API route that needs no login. Anyone can call it, so it must send only what a stranger may see.
- **NUL character** - The character with code 0 (`%00` in a URL, `\x00` in Python). Postgres cannot store it in text and raises an error.
- **Return None vs raise** - Returning `None` is an answer, and the next line runs. Raising an error stops the function; the error goes up until something catches it.
- **Fail closed** - When something needed is missing, the code stops instead of opening up. A forgotten tenant scope crashes; it never shows every Business's data.
- **Backfill** - Filling a new column for the rows that already exist, inside the migration.
- **Performance budget** - A hard limit, such as "first load ≤ 200 KB gzip", that CI checks on every PR.
- **gzip** - A way to squeeze files before they travel over the network. We count gzip bytes because that is about what a phone downloads.
- **Link header** - An HTTP response header that tells the browser to fetch a file early, such as a font. Next.js sends font preloads this way.
- **aria-live region** - A part of the page that a screen reader reads out when its text changes, such as "Link copied".
- **Request lifecycle** - The states one load goes through: loading, then ready, failed, or not found. `useLoad` (frontend/src/lib/useLoad.ts) owns it for every screen, so each screen only says what to fetch and how to show each state.
- **Hook** - A React function whose name starts with `use`. A component calls it to get state and actions, such as `useLoad`. Hooks must be called on every render, in the same order, so one cannot be skipped with an `if`.
- **Race condition (latest wins)** - Two requests run at once and answer in the wrong order, so an old answer overwrites a new one. `useLoad` numbers each request and drops every answer except the newest.
- **Deep module** - A module with a small interface and a lot of behaviour behind it. Callers learn little and get a lot. `useLoad` is one: 2 inputs, and it hides the states, retry, the 401 rule and the race fix.
- **Visitor token** - A random secret the server puts in a Chat Page browser's cookie. It is how a Customer with no account "comes back to the same chat". The database keeps only its hash.
- **Channel port** - A fixed shape (`inbox/channel.py`) that every chat channel plugs into: "find this sender's Conversation" and "open it, locked". The save logic talks only to the port.
- **Adapter** - The code that makes one real channel fit the port. `WebchatChannel` turns a cookie into a Conversation; a WhatsApp adapter would turn a phone number into one.
- **seq** - The number of a Message inside its Conversation: 1, 2, 3, … It gives one fixed order, and later lets the poll ask "anything after 7?".
- **Idempotent** - Doing it twice has the same effect as doing it once. A send with the same `client_message_id` saves one Message, so a retry after a lost answer is safe.
- **client_message_id** - A random id the browser makes for each new Message and sends again on a retry. The database refuses a second row with the same id in one Conversation.
- **Row lock (SELECT … FOR UPDATE)** - "Wait your turn" on one row. Other transactions that want the same lock wait until ours commits or rolls back.
- **Lock order** - Always take the locks in the same order (visitor row, then Conversation). Two requests that take them in opposite orders can wait for each other forever (a deadlock).
- **Identity map** - SQLAlchemy's in-memory copy of each row it already read in a session. A second read normally hands back that old copy; `populate_existing` makes a locked read refresh it.
- **CGNAT** - Carrier-grade NAT: a mobile carrier puts many phones behind one public IP address. So a per-IP limit must be generous, or many real Customers share one limit.
- **Poll** - The page asks the server "anything new?" again and again, every 5 s. Simple and works everywhere; the cost is many small requests, so each "no" answer must be cheap.
- **Cursor** - A bookmark the server gives the page: `v1.<business>.<last seq>.<version>`. The page sends it back on the next poll and never reads inside it. It is only a claim: the server checks it against the cookie.
- **Version counter** - A number in Redis per Conversation (`ver:...`). Every commit that changes the chat adds 1. If the page's number equals Redis's number, nothing changed.
- **Fast path / slow path** - Fast: answer "no change" from Redis only. Slow: read Postgres for the new Messages. The fast path is tried first; any doubt falls back to the slow path, which is always correct.
- **after_commit** - A SQLAlchemy event that runs after a transaction is saved for good. The version goes up here, not before: a poll must never see the new number before it can see the new row.
- **READ COMMITTED** - Postgres's default rule: each SQL statement sees every commit finished before it starts. So reading the version first and the Messages second can only make the page read again, never miss a Message.
- **Keyset pagination (keyset cursor)** - Paging by "start after the last row I saw" instead of "skip the first 20 rows" (OFFSET). A new row at the top shifts every OFFSET by one, so a row shows twice; a sort key does not shift. The Inbox cursor is `v1.<pinned>.<microseconds>.<id>`.
- **Tie-breaker** - A last sort column that is unique (here the id), so two rows with the same time always come in the same order and a page edge never splits them unpredictably.
- **Row compare** - SQL `(a, b, c) < (x, y, z)`: compare like words in a dictionary, first `a`, then `b` only on a tie, then `c`. One condition says "after the cursor row".
- **Denormalized column** - A copy of a fact kept on another row so a read is cheap. `conversations.last_message_at` copies the newest Message's time, so the Inbox sort never reads all Messages. Every writer must keep the copy up to date.
- **Expression index** - An index on a computed value, like `(state = 'handoff')`, not only on a plain column. A query can use it only when it says exactly the same expression.
- **Prepared statement / generic plan** - After a query runs a few times, the driver (psycopg) asks Postgres to plan it once and reuse the plan. With a parameter (`state = $1`) the reused "generic" plan cannot know the value is 'handoff', so it cannot use an index on `state = 'handoff'`. Writing 'handoff' as fixed SQL text avoids this.
- **Fail closed** - When a safety check cannot run (Redis is down, so no rate counter), refuse the request (503) instead of letting it through unchecked.
- **Handoff** - A person takes a chat from the Agent (the AI bot). While a chat is in Handoff, the Agent sends nothing. "Give back to Agent" ends it.
- **State machine** - A fixed list of states (`agent`, `handoff`, `closed`) and fixed moves between them. In SevaDesk only named functions (`start_handoff`, `end_handoff`) may make a move.
- **Code guard test** - A test that reads the source code (with Python's `ast` module) instead of running it, to enforce a rule such as "only these two functions write `state`".
- **Span event** - A timed note inside one span of a trace, with a few attributes. `conversation.state_changed {from, to}` records each Handoff change.
- **Stale-poll guard** - A poll that was asked before a click can answer after it, with older data. The screen keeps the click's state and its old cursor, so the next poll reads again.
- **Deadlock** - Two requests that each hold a lock the other one needs, so both wait forever. Postgres finds the circle and stops one with an error. Fixed by taking locks in one fixed order (see Lock order).
- **Right to erasure (DPDP delete)** - India's DPDP Act lets a person ask a Business to delete their data. In SevaDesk the Owner deletes a Customer with all their chats in one transaction (NFR-8).
- **Child-first delete** - Delete the rows that point at others (Messages) before the rows they point at (Customer). A foreign key refuses to delete a parent that still has children.
- **Tenant-filtered delete (`delete_where`)** - A DELETE that always adds "business_id = this Business", added in one place in the base repository, so no delete can reach another Business's rows.
- **Skipped deleted row (READ COMMITTED)** - A request that waits for a row lock, then sees that the row was deleted meanwhile, gets no row. Code that waits on a lock must handle "the row is gone" (`ensure_and_lock` makes it again).
- **Mutation check** - Break the code on purpose (remove one line), run the test, and see it fail. It proves the test really checks that line.
- **Sheet** - A panel that slides in from the side of the screen, on top of the page. A dialog, so focus stays inside it until it closes.
- **AlertDialog** - A dialog for a dangerous choice (like delete). It needs an explicit answer: Cancel or the action. A click outside does not close it.
- **Accessible description (`aria-describedby`)** - Extra text that a screen reader reads after a dialog's title. Radix links `SheetDescription` to the sheet by itself.
- **Live thread (`useLiveThread`)** - One chat that stays up to date on screen: load it, poll every 5 s, merge new Messages, keep this screen's own sends, ignore a poll older than a click, and end with "not found" if the chat was deleted. The Chat Page and the Inbox thread both use this one deep module; each only gives its two fetchers.
