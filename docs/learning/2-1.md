# Story 2.1: Owner signs up and creates a Business

## What was built
- `POST /api/v1/signup`: one request creates a Business, a User, and a membership with Roles `{owner, technician}`, in one transaction.
- Tenant context in `core`: `tenant_scope`, the audited `system_scope`, and the tenant-scoped base repository.
- Four tables (migration 0003): `businesses`, `users`, `sessions` (used from Story 2.2), `memberships`.
- One error envelope for every error: field errors (422), "email taken" (409), and crashes (500, no internal text).
- Frontend: shadcn/ui with the DESIGN.md tokens, Inter + Noto Sans Devanagari, and the `/signup` page.

## Why
- Many Businesses share one database. A forgotten `business_id` filter would show one Business's data to another. So the filter lives in one place (the base repository), and code with no Business set fails loudly.
- Passwords must never be readable, even by us. Argon2id makes a slow, salted, one-way hash.
- The backend owns every validation rule, so the form and the API never disagree.

## Data flow
Form (`SignupForm.tsx`) → `POST /api/v1/signup` → `business/schemas.py` checks and cleans the input → `business/router.py` (the request owns the transaction) → `business/service.py` inserts the Business, then sets `tenant_scope(new id)` → `accounts/service.py` `create_owner`: email lookup inside `system_scope`, Argon2id hash, insert User, insert membership → commit → 201. Any error before the commit → rollback → nothing saved.

## Key files
- `backend/app/core/tenancy.py` - which Business the code works for; the audited system scope (CORE)
- `backend/app/core/repository.py` - the tenant filter and tenant insert, in one place (CORE)
- `backend/app/modules/accounts/service.py` - the accounts front door; all password logic (CORE)
- `backend/app/modules/business/service.py` - the sign-up flow (CORE)
- `backend/migrations/versions/0003_accounts_and_business.py` - the four tables, with named constraints (CORE)
- `backend/app/core/errors.py` - the one error envelope (STANDARD)
- `frontend/src/components/SignupForm.tsx` - shows backend errors next to fields; focus on the first (STANDARD)
- `frontend/src/app/globals.css`, `frontend/src/components/ui/*` - brand tokens and shadcn parts (BOILERPLATE)

## Concepts learned
1. Multi-tenancy. One database, many Businesses. Every tenant row has `business_id`, and the base repository adds the filter, so no story can forget it.
2. ContextVar. A variable with its own value per request, so two sign-ups at the same moment never mix their Business.
3. Front door (AD-2). `business` calls `accounts` only through `accounts/service.py`. import-linter checks this in CI.
4. Argon2id. A slow password hash with a random salt. The same password gives a different hash each time, and the hash cannot be turned back.
5. One transaction. The request opens it and commits it. Services never commit. A crash anywhere means nothing is saved.
6. Design tokens. Named values (colors, radii, sizes). Components use names, so the theme changes in one file.

## Surprises
- Every `add()` must `flush()`: the UUIDv7 default fills `id` only when the INSERT is sent.
- Broken JSON gives the error location `("body", 1)`: a character position, not a field name.
- import-linter blocked `business → accounts.service → accounts.repository`. That indirect path is the front door working, so indirect imports are allowed.
- Live check: the local `.env` still sent traces to Grafana Cloud with the old, rotated token (401). Traces now go to the local Grafana by default.
