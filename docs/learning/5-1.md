# Story 5.1: Calculate free Slots

## What was built
- A new module `bookings`, which owns the new table `bookings` (`bookings/models.py`, migration `0011`).
  - 6 states: `requested`, `confirmed`, `declined`, `expired`, `completed`, `cancelled`.
  - Times are `timestamptz` UTC. Money is `price_paise`.
  - Composite foreign keys (FKs) to `customers`, `conversations`, and `memberships`. The database refuses a link into another Business.
  - CHECK rules: valid state, end after start, price > 0, a request needs `expires_at`, and a confirmed job needs a Technician.
- `bookings/slots.py`: the pure Slot math, with no database and no clock. Constants (AR-24): `SLOT_STEP_MINUTES = 30`, `SLOT_DAYS = 7`. The Slot length is the Service duration.
- `bookings/repository.py`: `is_live(now)` is the ONE "expired on read" rule. `live_between` reads the live Bookings in a time range.
- `bookings/service.py`: `list_free_slots`, the front door. It checks the Role first, then collects the facts, then calls the math.
- `business/service.py`: two new front-door functions, `get_active_service` and `business_timezone`.
- `GET /api/v1/bookings/slots?service_id=…`: Owner and Staff get 200. A Technician-only User gets 403, and a logged-out caller gets 401. Another Business's Service gives 404. The endpoint is in the isolation suite.
- import-linter: the new layer order is `inbox → bookings → business → accounts → core`, plus two front-door rules for `bookings`.
- Review fixes: the steps now count real time in UTC (DST: daylight saving time), more cross-Business link tests, the state-only "not live" test, and the equal-time edges.
- Hands-on (yours): `test_two_hour_service_fits_only_once`.

## Why
- FR-17: never promise a time when nobody can come. Later, the Agent (Epic 6) and the phone-in Booking (5.2) offer only these Slots.
- AR-7: only `accounts` knows who is an active Technician.
- AR-14: one rule for "expired", so every count agrees.

## Data flow
`GET /bookings/slots` → `ActorDep` (session → Actor → tenant scope) → `list_free_slots` → `require_roles` (403) → `business.get_active_service` (404) → `business.business_timezone` → "today" on the Business clock → `business.hours_on` × 7 days → `BookingRepository.live_between` (1 query, uses `is_live`) → `accounts.active_technician_ids` → `free_slots` (pure) → `FreeSlotsOut {timezone, slots[{start, end}] in UTC}`.

## Concepts learned
1. **Pure core, I/O at the edge:** the math gets plain values and returns plain values. So the unit tests need no database and run fast.
2. **Computed on read:** "expired" is never stored in this story. `requested AND expires_at > now` decides it at each read, so a request stops holding its Slot at the exact second it expires.
3. **NULL is never "true" in SQL:** `NULL > now` is not true. Without the CHECK, a request with no `expires_at` would never count, and two people could get the same Slot.
4. **Half-open ranges `[start, end)`:** a job that ends at 11:00 does not clash with a Slot that starts at 11:00. Use `<` on both edges.
5. **Business date ≠ UTC date:** at 00:30 in India it is still yesterday in UTC. Always work out "today" in the Business timezone.
6. **Do time math in UTC:** "+30 min" on a clock time can skip or repeat an hour on a DST day. In UTC, every step is 30 real minutes.
7. **One-way imports, database-checked links:** `bookings` keeps `customer_id` as a plain id. Python has no import loop, and the composite FK still guards the link.
8. **Test with defaults (`starts(**changes)`):** each test changes only the input it cares about.
9. **A test that passes for the wrong reason proves nothing:** the first DST test failed only because "now" was after the test day. A red test must fail for the reason you expect.
