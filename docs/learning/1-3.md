# Story 1.3: Eval harness with a placeholder Eval

## What was built
One command runs the evals: `uv run --project backend python -m evals.runner` (from the repo root).
It runs one test case on a placeholder agent, prints a score per check, saves the result, and exits with a code that CI can read.

## Why
An AI does not give the same answer every time, and a small prompt change can make it worse. Normal tests cannot see that. An Eval is an automated exam for the AI. We build the exam now, before the real Agent exists, so every later change to the Agent is measured from day one.

## Data flow
`dataset.json` (cases) -> `placeholder_agent.reply()` -> each check in `checks.py` says True or False -> `score_checks()` -> `compare_to_baseline()` with `baseline.json` -> print the scores + `PASS`/`FAIL` -> save `results/latest.json` -> exit code.

## Concepts learned
1. Eval, case, check. A case is one test message with the expected result. A check is a small piece of code that looks at one reply and says pass or fail.
2. Score. A score is the share of cases that passed one check, from 0.00 to 1.00. Example: 1 of 2 cases passed, so the score is 0.50. Zero cases is an error, not a score.
3. Baseline. The baseline is the best score so far, saved in the repo. A score below it fails the run. A score equal to it passes. A check that disappears from the run also fails. A new check with no baseline does not fail.
4. Exit code as a CI signal. `0` = pass. `1` = the AI did worse than the baseline. `2` = the exam could not run (a file is missing, broken, or has no cases). CI reads this number to block a merge.
5. Versions in every result. Each result names `prompt_version` and `dataset_version`. When a score changes, they show which one changed: the AI's instructions or the test cases.
6. Placeholder. A simple stand-in for something that does not exist yet. Our placeholder agent always gives the same reply. Epic 6 replaces it with the real Agent.
