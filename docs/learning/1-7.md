# Story 1.7: One-command AWS staging deploy and destroy

## What was built
One command (`infra/terraform/deploy.sh <sha>`) builds the whole app on AWS in Mumbai and checks the live page. One command (`infra/terraform/destroy.sh`) deletes it all and proves that nothing which costs money is left. Both run from the laptop or from a GitHub workflow that waits for your approval.

## Why
AWS is the cloud most job descriptions name. Staging shows that SevaDesk runs on "real" AWS parts (ECS, RDS, ElastiCache, ALB). But it costs about $3 per day, so it must be easy to switch on for an interview and easy to switch off after.

## Data flow
Laptop or GitHub (approved) → borrow role `sevadesk-deployer` → Terraform reads its memory (state) from S3 → creates network, firewalls, RDS, Valkey, secret, ALB, 3 Fargate services → backend container starts: `alembic upgrade head`, then Uvicorn → ALB health check passes → `deploy.sh` calls `http://<alb>/api/v1/hello` and checks `version == SHA`.

Browser → ALB :80 → `/api/*` → FastAPI → RDS + Valkey; everything else → Next.js.

## Concepts learned
1. **Infrastructure as code.** Terraform makes the cloud match text files. `plan` shows the change, `apply` makes it, `destroy` removes it.
2. **State is memory.** Terraform knows what it made only from the state file. Shared state in S3 lets the laptop and GitHub manage the same staging.
3. **Borrow, don't store.** No AWS keys in GitHub. GitHub gets a short-lived token, and AWS trusts it only from environment `aws-staging` of this repo.
4. **Permissions boundary.** A hard upper limit on a role. The deployer may create roles only with the boundary on them, so it can never create an admin.
5. **Two locks on the database.** No public address (`publicly_accessible = false`) AND a firewall that admits only the app containers.
6. **Same image everywhere.** AWS runs the exact GHCR images of the commit. The image's own CMD runs the migration before Uvicorn, so AWS needs no extra migration step.
7. **Test infrastructure for free.** `terraform test` with a mock provider checks the rules (routing, firewalls, deletion settings) with no AWS account.

## Surprises
- **Zones run out of small machines.** Deploy 1 and 2 failed: `db.t4g.micro` and `cache.t4g.micro` were sold out in `ap-south-1a` and `1b`. Only `1c` had space. Fix: a subnet in every zone (RDS then picks a zone with space by itself) and a chosen zone for Valkey (`var.cache_az`, default `1c`), because ElastiCache does not pick by itself.
- **A failed create blocks Terraform.** A Valkey cache stuck in `create-failed` makes every later plan stop, because Terraform must read it first. We deleted it by hand; the runbook has the command.
- **First use of a service** makes AWS create a helper role (service-linked role). For ElastiCache the first call failed with `408 ... try again` while that happened.
- **Git Bash changes `/ecs/...` into a Windows path.** Use `MSYS_NO_PATHCONV=1` for AWS commands with such arguments.
- **Shared AWS account.** Other projects live in the same account. So the budget covers them too, and the clean check looks only at resources tagged `sevadesk`.
- **Destroy worked first time:** 42 resources removed, and `check-clean.sh` said `clean` on its first try.
- **Cost of this story's live test:** about $0.20–0.30 (three deploy attempts, about 1.5 hours of a load balancer, then one successful run and a destroy).
