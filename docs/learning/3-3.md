# Story 3.3: Share the Chat Page link

## What was built
- A new column `businesses.chat_slug` (NOT NULL, UNIQUE), in migration 0008. `make_chat_slug("Café Ravi")` makes `cafe-ravi-94j2w5`: the name in plain letters, then 6 random characters. A name with no Latin letters gets `chat-xxxxxx`.
- `GET /api/v1/setup` (Owner only): the slug, `has_services` (at least one ACTIVE Service), and `has_working_hours`.
- `GET /api/v1/chat/{chat_slug}` (public, no login): the Business name, `taking_requests`, and the active Services. It sends no ids.
- Frontend: Settings → Chat link (`/app/settings/chat-link`), the Dashboard checklist (Add Services → Set Working Hours → Copy chat link), and the public Chat Page `/c/{slug}` with the DPDP notice.
- CI: "Build frontend" and "Chat Page size check (NFR-6, ≤ 200 KB)". The check fails the build if the Chat Page first load is over 204,800 bytes gzip.

## Why
- The tenant of the public page comes from the **slug only** (AD-3 b). The route has no `ActorDep`, so a logged-in Owner A who opens B's link sees B's page.
- The migration fills old rows in SQL (`md5(id)`), not with `make_chat_slug`. A migration must do the same thing forever, and app code changes.
- The slug shape (`[a-z0-9-]{1,40}`) is checked BEFORE the database. A NUL character (`%00`) would make Postgres raise an error (500). With the check, it is a clean 404.
- Customers use cheap phones on slow data, so the Chat Page has a hard size budget. It is measured on the real production build in CI.

## Data flow
Customer opens `/c/cafe-ravi-94j2w5` → `app/c/[slug]/page.tsx` reads the slug → `<ChatPage>` → `load` sends `GET /api/v1/chat/cafe-ravi-94j2w5` → Caddy → FastAPI `get_chat_page` (no cookie read) → lowercase + shape check → `find_by_chat_slug` → `tenant_scope(business.id)` → `list_active()` + `_is_set_up` → JSON `ChatPageOut` → the browser formats `49900` as "from ₹499" (`formatRupees`) and `60` as "1 h" (`formatDuration`).

## Concepts learned
1. A tenant can come from a public key in the URL (the slug), not only from a session cookie.
2. **Return `None` vs raise an error:** `None` is an answer, and the next line runs. An error stops the function and goes up until something catches it; if nothing does, FastAPI answers 500.
3. Fail closed: a forgotten `tenant_scope` makes `current_business_id()` raise. That is a crash, never a leak.
4. Validate untrusted input at the door, before slow or fragile parts (the database) see it.
5. Adding a NOT NULL column to a table with rows: add it nullable → fill the rows → set NOT NULL.
6. A performance budget only works if a machine checks it on every PR.

## Size numbers (NFR-6)
- Stub page (only `<main />`): 144,386 B without the font, **192,828 B** with it. The framework and the Inter font take most of the budget.
- First real page: 210,045 B (over). The shared `ui/button` pulled in `radix-ui`. A plain `<button>` fixed it: **197,177 B**.
- About 7.6 KB is left for Epic 4's chat. Plan for lazy loading there.

## Surprises
- Next.js sends the font preload in the HTTP `Link` header, not in the HTML. The first size script missed a 48 KB font.
- `infra/compose/.env` sends traces to Grafana Cloud, so the local Tempo was empty. That is by design.
- Git Bash on Windows breaks non-ASCII text (`é`) in `curl -d`. Send the body from a UTF-8 file instead.
- The final review found two real UX problems that tests did not catch: an empty Services box, and "Copied" not read out to screen readers.
